swimmerGB.js - low-poly swimmer / slide rider for the World IIFE
======================================================================

What it defines (plain JS, drop into the World IIFE next to treeGB/rockGB):
  SWIM_SKIN        3 fixed skin tones (cream = reference, tan, brown)
  PALETTES         6 fixed suit palettes {name, a, b, cap, strap} (a = stripe A, b = stripe B):
                     red/white (reference), blue/white, yellow/white, teal/white, pink/white,
                     navy (solid suit: a = b = navy, white cap)
                   cap and strap must equal a, b or white; they are encoded as a *source*, not a colour.
  swimmerGB(pose)  returns a GB; also sets g.seat (lowest y) and g.tris
  pickVariant(rnd[,pal])  rnd = function returning [0,1). Picks a palette (or the given index), applies
                   ~+-4% brightness and a small hue shift, picks a skin tone (60% cream, 25% tan, 15% brown).
                   Returns {pal, a, b, skin, icol:[r,g,b,packed]}.
  swimmerTint(icol,i,v)   icol.set(v.icol, i*4)
  swimPack / swimSrc      internal helpers (packing).
  Does NOT define riderGB.

GB methods relied on: new GB(), g.tri(a,b,c,col,wa,wb,wc) (wa/wb/wc = per-vertex alpha), g.p (read only,
for the seat/bounds). No cyl/box/quad: limbs/torso use internal tube/ring/wedge helpers built on g.tri,
each face's winding is flipped to point away from an interior point so the flat normals face outward.

Axes / origin
  y up, metres, faces +Z, arms along +-X. Origin = PELVIS (midpoint of the hip joints) in every pose.
  Pose 0 is ~1.70 m: feet at y=-0.864, cap top at +0.84, arm span 1.63 m.
  g.seat = lowest y of the pose; to rest a rider on a surface at height h, put the instance at y = h - g.seat.

Poses (triangles: 434 each, all poses share the same topology)
  0  reference T-pose                                            seat -0.864  bounds x+-0.81 z -0.10..0.15
  1  slide sitting: seated feet-first (+Z), legs forward slightly apart, torso leaning back 18 deg,
     arms up in a V cheer                                        seat -0.112  y up to 1.06, z -0.33..0.90
  2  slide lying back: reclined (torso 79 deg back), feet +Z, head -Z, chin tucked, hands behind head,
     elbows out                                                  seat -0.095  z -0.78..0.89
  3  splash dive: streamlined, belly down (-Y), head + arms toward +Z, legs/pointed feet toward -Z
     (pitch the instance for a nose-down dive)                   seat -0.119  z -0.96..1.11
  The slide's direction of travel should map to the rider's +Z (feet first for poses 1 and 2).

Colours / tint scheme
  RGB baked per face = the reference look (cream skin, red cap/straps/red stripes, white stripes), so with
  the stock shader and the default icol (1,1,1,1) every rider looks like the reference.
  The vertex-colour ALPHA is a material mask (alpha is only used as sway weight when 1.5<uMat<3.5):
     0.00 skin   0.25 cap   0.50 stripe B   0.75 straps   1.00 stripe A
  Per-instance data stays the existing 4-float icol (no new attribute):
     icol.rgb = stripe A colour
     icol.a   = packed integer, exact in float32 (< 2^23):
                bits 0-17 stripe B rgb, 6 bits per channel (r<<12|g<<6|b)
                bits 18-19 cap source (0 = A, 1 = B, 2 = white)
                bit  20    strap source (0 = A, 1 = B)
                bits 21-22 skin tone index into SWIM_SKIN
     icol.a <= 1.5 -> no decoding (stock multiply by icol.rgb).

Integration steps
  1. Paste swimmerGB.js into the World IIFE (after the GB class exists, e.g. after flowerGB).
  2. Build: const sw=[0,1,2,3].map(p=>meshFromGB(swimmerGB(p),{inst:64,mat:5}));
     (mat 5 is unused: the game uses 0,1,2,3,3.2,4; the litFS has no uMat==5 branch, so it shades like mat 0.)
  3. litVS: add the skin table above main() and replace  vC=vec4(aCol.rgb*iC.rgb,aCol.a);  with
       const vec3 SWSK[3]=vec3[3](vec3(0.95,0.87,0.63),vec3(0.87,0.70,0.52),vec3(0.58,0.41,0.30));
       ...
       vec3 c=aCol.rgb*iC.rgb;
       if(uMat>4.5&&uMat<5.5&&iC.a>1.5){int p=int(iC.a+0.5);
         vec3 B=vec3(float((p>>12)&63),float((p>>6)&63),float(p&63))/63.0;
         int cs=(p>>18)&3,ss=(p>>20)&1,sk=min((p>>21)&3,2);float m=aCol.a;
         c=m<0.125?SWSK[sk]:m<0.375?(cs==0?iC.rgb:cs==1?B:vec3(0.95)):m<0.625?B:m<0.875?(ss==0?iC.rgb:B):iC.rgb;}
       vC=vec4(c,aCol.a);
     (Keep SWSK in sync with SWIM_SKIN. The depth pass uses the same VS and is unaffected.)
  4. Per rider, once at spawn: r.v=pickVariant(rnd);  per frame:
       writeYZ(sw[pose].inst,n,x,surfaceY-seat[pose],z,yaw,0,1)  (or writeYX to pitch along the slide)
       swimmerTint(sw[pose].icol,n,r.v); n++;   then instUpload(sw[pose],n);
     Cache g.seat per pose at build time (meshFromGB drops extra GB fields): const seat=[0,1,2,3].map(p=>swimmerGB(p).seat)
     or simply use -0.11 for poses 1-3.

Limitations
  434 triangles (a bit above 400): 9 suit bands x 8 sides dominate. Not rigged: poses are baked, one mesh
  per pose. The stripe B colour is quantised to 6 bits/channel. Hands are simple mitten wedges.
