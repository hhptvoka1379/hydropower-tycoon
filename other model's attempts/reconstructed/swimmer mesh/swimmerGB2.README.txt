swimmerGB2.js - low-poly swimmer / slide rider with body-shape variants (v2 of swimmerGB.js)
==========================================================================================

Drop-in REPLACEMENT for swimmerGB.js (same names: SWIM_SKIN, PALETTES, swimPack, swimSrc, pickVariant,
swimmerTint, swimmerGB). Paste one or the other into the World IIFE, not both. swimmerGB(pose) with no body
still builds the v1 reference figure (1.70 m, cap, striped suit; only change: one extra thigh ring, 454 tris).

New definitions
  SWIM_HAIR            5 hair colours: light brown, dark brown, black, blonde, auburn
  SWIM_LOOK            8 [skin, hair] pairs, indexed by the 3-bit LOOK field of the packed tint
                       0 cream/lt-brown 1 tan/dk-brown 2 brown/black 3 cream/blonde 4 cream/auburn
                       5 tan/black 6 brown/dk-brown 7 tan/lt-brown   (0-2 = the v1 skin indices)
  SWIM_BODY_DEFAULT    the reference descriptor (fills any field a body leaves out)
  BODIES               10 presets (below)
  pickBody(rnd[,weights])  -> {id, name, body, scale}
  swimmerGB(pose, body)    -> GB, plus g.seat (lowest y), g.top, g.tris, g.body
  pickVariant(rnd[,pal[,look]]) now also returns .look (skin+hair) and packs it in bits 21-23.

GB methods relied on: new GB(), g.tri(a,b,c,col,wa,wb,wc), g.p (read for seat/bounds). Nothing else.
Axes / origin unchanged: y up, metres, faces +Z, arms along +-X, origin = pelvis in every pose.

Body descriptor (all continuous unless noted; 1 = reference)
  height     total standing height, sole to crown, metres (T-pose height matches to ~1 mm; tested 1.10-1.95)
             The figure is built in unit proportions and uniformly scaled to this height, so legs/head/neck
             change PROPORTIONS and height sets the absolute size.
  build      0 slim .. 0.5 average .. 1 stocky/heavy: torso width (x0.75..1.25) and depth (x0.72..1.27),
             limb thickness (x0.7..1.3); above 0.6 adds a slight belly
  shoulders  shoulder width (also thickens neck and upper arms above 1)
  bust       0 flat .. 0.5 reference .. 1 full: modest front-only bulge (max 5 cm), never on the back;
             0.1-0.2 on the masculine bodies gives a slight pectoral plane
  waist, hips  widths (hips also widens the thigh tops so wide hips don't read as a skirt)
  legs, arms   length multipliers
  head, neck   head size, neck length
  child      0..1 child proportions on top of the rest: head x1.55, neck x0.65, legs x0.88, arms x0.92,
             softer waist, bust forced to 0, slightly rounder jaw
  hair       'cap' (swim cap, cap mask)  'short'  'bun' (+12 tris)  'ponytail' (+25 tris)
             bare hair uses the new HAIR mask; its colour comes from the instance LOOK (SWIM_LOOK)
  suit       'striped' one-piece (v1)  'plain' one-piece (all stripe A)  'twopiece' (sporty crop top with
             A/B/A bands + bottoms with a B waistband, bare midriff)  'trunks' (bare torso, swim trunks in A
             with a B waistband, trunk legs to mid-thigh, no straps)

Tint mask / shader (vertex-colour alpha; per-instance icol unchanged: rgb = stripe A, a = packed int)
  alpha 0.000 skin  0.125 HAIR (new)  0.25 cap  0.50 stripe B  0.75 straps  1.00 stripe A
  packed: bits 0-17 stripe B rgb 6/6/6 | 18-19 cap source | 20 strap source | 21-23 LOOK (was: 21-22 skin)
  The largest packed value is < 2^24, so it is still exact in float32.

Mesh count and keeping it cheap
  Single mesh per (body, pose) as before: 10 bodies x 4 poses = 40 small meshes max, ~460 tris each
  = ~18.4k tris, ~55k non-indexed verts (~2.2 MB of position+normal+colour floats) if ALL are built. Each
  (body, pose) is one instanced draw call per frame when it has riders, so worst case 40 extra draws.
  Keep it cheap:
   - build lazily and only the poses in use: const SW={}; function sw(id,pose){const k=id*4+pose;
       if(!SW[k]){const g=swimmerGB(pose,BODIES[id]);SW[k]=meshFromGB(g,{inst:24,mat:5});SW[k].seat=g.seat;}return SW[k];}
     The slide only needs poses 1 and 2 (20 meshes); the T-pose is only for previews; dive only at the splash.
   - pickBody(rnd, weights) with zeros for presets you don't want (e.g. ship 6 bodies -> 12 slide meshes).
   - jitter for free: pickBody returns `scale` (+-3% height). Use the cached BODIES[id] mesh and scale the
     instance matrix uniformly by `scale`; the seat offset becomes seat*scale (y = surface - seat*scale).
     The other jittered fields in `body` (build, hips, ...) only take effect if you build a one-off mesh from
     `body` (fine for a hero/close-up rider, not for crowds - every call would be a new mesh).
   - skin/hair/suit colours are per instance (icol), so they never multiply the mesh count.
  Per rider at spawn: r.b=pickBody(rnd); r.v=pickVariant(rnd);  per frame:
    const M=sw(r.b.id,pose); write the instance matrix at (x, surfaceY - M.seat*r.b.scale, z) with uniform
    scale r.b.scale; swimmerTint(M.icol,n,r.v);  then instUpload per used mesh.

Limitations
  - Still not rigged: each (body, pose) is a baked mesh. Poses are the same joint angles for every body, so
    e.g. the hands-behind-head pose aims the forearms at the head of each body but short arms may not quite reach.
  - Hair is a cap-shaped hair region plus a bun or ponytail; no long loose hair. The ponytail direction is
    set per pose (hangs in T/sit, lies on the slide when lying back, trails behind in the dive).
  - Wide-hip bodies keep a visible facet step between the suit's leg opening and the thigh tops (8-sided
    torso, 5-sided limbs); trunks read as boxer-style shorts with a small inner-leg seam visible when seated.
  - Feet/hands are the v1 wedges scaled with build; there are no face features beyond the faceted nose/chin.
  - Stripe B stays 6 bits/channel; only 8 skin+hair combinations (3 bits) fit in the packed float.
